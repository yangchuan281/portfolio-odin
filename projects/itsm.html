01 context

Four ledgers, and none of them agreed.

The intranet ran on four books that never met: an Excel sheet of devices, a password file nobody owned, certificate expiry dates in someone's calendar, and tickets living in private chats.

So the platform keeps one. Every device, credential, certificate and ticket sits in the same schema, and every write leaves an audit row. The point is not the forms — it is that the books can no longer drift apart: a ticket knows its alert, an alert knows its device, and the device knows which rack unit and which address it occupies.

02 design

Boring on purpose: one process, one file, no install.

Node 22's built-in http and node:sqlite instead of Express and PostgreSQL. The whole thing starts with node server.js on an offline intranet box — no private npm registry, no install step, nothing to patch on a Sunday.

The cost is stated instead of hidden: one node, no horizontal scaling. Data access is concentrated in src/modules/*, so moving to PostgreSQL later is a contained job rather than a rewrite.

03 what is not there

Four menus say "not enabled", and they mean it.

Service dependencies, subnet governance, reachability analysis and policy health ship as a menu with a paragraph explaining why — not as a table that pretends to be empty. Nothing behind them is faked; the link simply is not built yet.

The rest of the gap is in the README rather than in a changelog nobody reads: no SMS, no live LDAP sign-on (import only), no ticket attachments, no multi-tenant mode, and outbound notification is best-effort with backoff — not at-least-once.

Known limits — stated, not discovered later

  • One node on SQLite: sized for a few hundred people on one intranet team, not a cluster. Multi-node means PostgreSQL first.
  • The four menu items above are placeholders by design — the page explains the gap instead of listing empty rows.
  • LDAP is import-only: accounts arrive with a one-time password, but login never binds against the directory.
  • Verified against a seeded database and the test suite — not against a production intranet with real credential churn and a real audit.
